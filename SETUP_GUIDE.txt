WHAT YOU MUST DO YOURSELF (3 things) ⚠️
──────────────────────────────────────────────

THING 1 — Fill in your Firebase credentials
  File to edit: src/environments/environment.ts
  Template:    src/environments/environment.example.ts

  Start from the example file:
     cp src/environments/environment.example.ts src/environments/environment.ts
     (Windows: copy src\environments\environment.example.ts src\environments\environment.ts)

  Then replace each PASTE_YOUR_xxx_HERE with your real values.
  Get them from: Firebase Console → Project Settings → Your Apps → </>

  environment.prod.ts is swapped in automatically for production builds
  (see fileReplacements in angular.json), so fill in the same values there
  before deploying.

THING 2 — Add your Service Account Key
  File to add: scripts/serviceAccountKey.json  (git-ignored — never commit it)

  Get it from: Firebase Console → Project Settings → Service Accounts
               → Generate new private key → download the .json file
  Rename it to: serviceAccountKey.json
  Place it in:  the scripts/ folder

  Only needed for `npm run seed`. The app itself does not use it.

THING 3 — Connect Cloudinary (for Add Product images)
  File to edit: src/environments/environment.ts (and environment.prod.ts)

  1. Sign up at cloudinary.com (free plan is enough)
  2. Copy your Cloud Name from the Dashboard top
  3. Go to: Settings (gear) → Upload → Upload presets → Add upload preset
     - Signing Mode: Unsigned → Save
     - Copy the Preset name
  4. Paste both into the cloudinary block:
       cloudinary: { cloudName: 'your-name', uploadPreset: 'your-preset' }
  Until then, image upload shows a warning and products save without an image.

  Tightening the preset (optional but recommended — an unsigned preset is a
  public drop box, so anyone who learns its name can upload):
     - Max file size: ~4 MB
     - Allowed formats: jpg, png, webp
     - Folder: five-orites-scoop/products
     - Leave "Incoming moderation" OFF. Turning it on sends every product
       photo into a manual approval queue and Add Product will show broken
       images until each one is approved.

  IMAGE SIZING IS AUTOMATIC
  Uploaded files are downscaled to 1024px before upload, and the CloudinaryPipe
  (`src/app/shared/pipes/cloudinary.pipe.ts`) resizes on delivery per screen:
  grid 400px, product page 1000px, cart 200px — with f_auto/q_auto, so modern
  browsers get WebP automatically. One stored file serves every screen size, so
  there is nothing to configure and no need to re-upload existing images.

STEPS TO RUN THE APP
──────────────────────
1. Open this folder in VS Code
2. Open terminal (Ctrl + `)
3. Run: npm install
   (if peer-dependency errors appear, retry with npm install --legacy-peer-deps)
4. Run: npm run typecheck      (optional sanity check — no Firebase needed)
5. Run: npm run test:logic     (optional — 18 business-logic tests)
6. Run: npm run seed           (writes 64 products to Firestore)
7. Run: npm start              (dev server, opens in browser)
8. Open: http://localhost:4200

VERIFYING A PRODUCTION BUILD
────────────────────────────
  npm run build        → output lands in www/browser
  firebase deploy --only hosting

  Note: both firebase.json (hosting.public) and capacitor.config.ts (webDir)
  point at www/browser, because that is where Angular 17's application builder
  writes. Do not change one without the other.

FIREBASE SETUP CHECKLIST
──────────────────────────
□ Created Firebase project at console.firebase.google.com
□ Enabled Firestore Database (Build → Firestore → Create database)
□ Enabled Authentication → Email/Password + Google sign-in
□ Registered a Web App (Project Settings → </> icon)
□ Copied credentials into src/environments/environment.ts
  (and environment.prod.ts before deploying)
□ Downloaded service account key → renamed → placed in scripts/
□ Ran: npm run seed  (seeds 64 products)
□ Ran: firebase deploy --only firestore  (applies security rules + indexes)
□ Promoted your first admin:
  Sign in through the app once FIRST — that is what creates users/{uid}.
  Then:  npm run seed:admin -- <your-uid> owner

  (The security rules read the `role` field on the user document; there are no
  custom claims. Only an OWNER can promote anyone else afterwards, from
  Admin → Users.)

  The script validates the role against the same vocabulary the app and the rules
  use, and refuses anything malformed. Doing this by hand in the console is what
  produced a real incident here: a role pasted as "owner\n" matches no tier, so the
  owner lost every admin page with no error anywhere, and recovery meant another
  manual edit.
